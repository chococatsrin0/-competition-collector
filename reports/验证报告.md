# Binance 交易锦标赛采集器 —— 验证报告

日期：2026-08-09

## 一、探索流程（Explore → Hypothesis → Inspect → Capture → Code → Test → Fix → Repeat）

### 1. 浏览器探索

使用 Playwright（真实 Chromium）打开币安公告页、公告详情页、交易锦标赛活动页，捕获全部 `/bapi/` 网络请求。

### 2. 发现的真实接口（均经浏览器 Network 捕获并逐一用代码验证）

接口清单：

- 公告列表：`GET /bapi/apex/v1/public/apex/cms/article/list/query`，参数 `type=1&pageNo&pageSize&catalogId=93`，请求头 `lang: zh-CN` 返回中文标题
- 公告详情：`GET /bapi/composite/v1/public/cms/article/detail/query?articleCode=<code>`，返回富文本 body（JSON），内含「立即参与 / Join Now」按钮链接
- 参与人数：`POST /bapi/growth/v1/friendly/growth-paas/resource/summary/participant/list`，body `{resourceIdList:[...]}`
- 排行榜：`POST /bapi/growth/v1/friendly/growth-paas/resource/summary/list`，body `{resourceId, leaderboardType:"USER", pageIndex, pageSize}`，返回 `total` 与 `data[]`

### 3. 关键发现

- 活动 URL 不在拼接里：公告正文富文本中的按钮节点携带真实链接（`attr.href`，含 `%suffixOrigin%` 占位符，替换为 `binance.com`）。
- resourceId 来源：活动页 HTML 内嵌 `__APP_DATA` JSON，其中 `activities[]` 的 `i18nContent.title == "主奖池"`（兜底 `globalContent.uri == "Main-Reward"`）即主奖池资源；`rewardPoolSetting.unit` 为币种 Token；`timelineContent` 为活动起止时间；`rankingPrizeList` 为奖励档次。
- AWS WAF 挑战：公告详情页/活动页对纯 HTTP 客户端返回 `x-amzn-waf-action: challenge`（202），必须用真实浏览器（Playwright）抓取；三个 API 接口不受影响。
- 语言参数：公告列表 API 需请求头 `lang: zh-CN` 才返回中文标题。

## 三、迭代中修复的问题

1. WAF 抖动：活动页首次加载偶发返回挑战页（无 `__APP_DATA`），增加浏览器重试（最多 3 次，失败重置上下文）。
2. 采集过慢：排行榜分页串行（11k-64k 行的比赛需 4-20 分钟），改为 4 线程并发分页、按页序合并，速度提升约 4 倍。
3. 历史活动过多：发现阶段会捞到近一个月的锦标赛，全量采集超过 1 小时；增加「最近 N 天发布」过滤（默认 7 天，`--days` 可调），单轮控制在 2-5 分钟。
4. 调度器默认值：`run_collection()` 默认未带时间窗口，定时任务会全量采集；已修复为默认 7 天窗口。
5. 测试污染：CSV 单测曾把样例写入真实 data 目录，已改为 mock 临时目录。
